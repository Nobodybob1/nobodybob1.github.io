How I work

I like the part before the obvious solution exists.

The useful work is rarely another dashboard. It's finding the real constraint under the request, making the logic explicit in code and data, and shipping a system that survives contact with reality.

01 / FRAME

Find the actual problem.

Separate symptoms from constraints. Map the data, the stakeholders, and where human judgment still has to stay in the loop.

Energy Orchestrator: the constraint was the transformer (100 kW / 700 kW limits), not any single device.

02 / MODEL

Make the logic inspectable.

Turn tacit reasoning into schemas, states, policies and pipelines that can be tested, challenged and improved.

GRCentric: document jobs go through a queued Python worker with a lock against concurrent runs, so the AI pipeline runs predictably.

03 / SHIP

Build the smallest credible system.

Get something real in front of users, then measure whether it actually moves the number that matters.

Energy Orchestrator: judged on KPI targets in 8- and 30-house simulations, not demos.
